# 0.3.0-dev（尚未发布）

- 新增系统设置，支持名称、Logo、工作模块时区和上传上限，保存前后值用于审计。
- 工作台展示真实申请、待办和未读消息；角色表单增加常用模板与数据权限说明。
- 新增单人审批：指定审批人、附件、通过、驳回、撤回和完整处理记录。
- 新增站内通知、未读计数和消息跳转；事务保证审批结果与通知一致。
- 事项及附件仅参与人可读，禁止自审；重复处理返回冲突，审批附件不可删除。
- 支持事项搜索、状态筛选，以及驳回/撤回后修改重提；新申请关联来源，原审批记录保持不变。
- 新增个人未使用附件复用、回收与恢复、容量统计和管理员到期清理；保留期默认 30 天，可设 7–365 天，清理失败可重试。
- 数据库升级至 schema 3，保留原有账号、菜单、系统设置、文件和审批记录；旧文件不自动改为事项附件。
- 修复 MySQL 建表注释的 DDL 参数问题、Docker 忽略规则误删前端页面，以及 CI 浏览器安装环境兼容问题。
- 修复 SQLite 多连接下读取后写入事务的锁冲突；回退测试使用有效迁移时间，兼容 MySQL 严格日期模式。
- 自动验收覆盖双账号审批、权限隔离、附件维护、并发决定、设置、升级与恢复；后端最低 Go 1.24。

升级前备份数据库和应用数据。schema 3 不能直接切回 0.2 或使用 schema 2 的早期 0.3 开发版镜像，需恢复升级前备份。

# 0.2.0

- 新增首次安装向导，初始化系统名称和管理员；使用服务器安装授权码防止远程抢占。
- 自动生成并持久化独立 JWT 密钥，停止创建公开默认账号。
- 账号禁用、删除、改密后旧令牌失效；退出登录记录持久化到数据库，SQLite 无 Redis 也可撤销会话。
- 用户写操作校验数据范围，私有文件按上传者隔离；组织与权限配置写操作仅超级管理员可执行。
- 应用数据目录持久化；文件搜索兼容 PostgreSQL、MySQL、SQLite 和 SQL Server。
- 新增数据库迁移记录、版本信息、升级与回退指引，以及发布前的自动检查。

升级注意：旧登录令牌全部失效。使用已知默认密码的 admin 账号需先修改密码；默认密码的普通 user 账号将停用。请部署前阅读升级指引。
