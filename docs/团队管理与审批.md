# 团队管理与审批（0.3 开发版）

## 初始化一个团队

1. 完成安装并登录超级管理员。
2. 在“系统管理 → 系统设置”填写系统名称、Logo、显示时区和单文件上传上限。保存后生效，无需重启。数据库、存储路径和密钥仍由部署配置维护。
3. 在“部门管理”建立组织结构，在“用户管理”创建启用账号并分配部门。
4. 在“角色管理”使用团队成员、部门负责人或审阅人员模板，填写唯一编码和标识，确认勾选的权限后保存，再给用户分配角色。

模板只是可编辑的初始值，不赋予超级管理员身份。多个启用角色的权限取并集；赋予“全部数据”会扩大其他角色的数据范围。组织与权限配置写操作仍仅超级管理员可执行。

“工作台、事项与审批、站内通知”是启用账号的基础入口，不依赖角色菜单配置。用户管理等系统功能继续由 RBAC 控制。文件管理仍按上传者隔离，超级管理员可以管理文件；事项附件则使用单独的参与人校验。

## 提交和处理事项

- 在“事项与审批 → 新建申请”填写标题、说明并指定另一位启用用户作为审批人。搜索返回最多 50 个账号的姓名、登录名和编码，不返回联系方式等资料。
- 支持最多 10 个附件，单文件大小遵循系统设置。仅能关联自己的有效文件。成功提交后，附件保留作为审批凭证，不能从文件管理删除。
- 审批人在工作台和“待我审批”查看待办，也可从站内通知打开事项。可以通过或驳回；驳回必须填写原因。
- 申请人可以撤回尚未处理的申请。审批人停用后，申请人可撤回并重新指定其他审批人提交。
- 已通过、驳回或撤回的事项不可再次处理。如需修改，重新提交一份申请；第一版不提供转交、加签、多级审批、流程设计器或业务表单配置。

系统管理员不会因为管理权限而自动看到所有事项，也不能代替审批人处理。事项正文、附件下载和审批记录仅对申请人及指定审批人开放。附件下载入口位于事项详情，不需要额外授予文件管理权限。

事务同时保存处理结果、审批记录和通知；并发提交不同决定时只允许一个成功，其他操作返回冲突并提示刷新。上传但未提交的文件仍保存在文件存储中，尚未关联审批，不属于审批凭证。

## 消息与时间显示

通知只对收件人可见，支持单条查看后标已读、全部标已读及仅看未读。页头计数每分钟刷新，回到窗口或当前窗口发生相关操作也会更新；不包含邮件、短信或即时推送。

设置中的时区用于工作台、事项、通知和设置修改记录；其他已有页面继续使用原有时间显示。时间在数据库中保持原始时间值，不因显示时区设置而改写。

## 验证和升级

运行仓库根目录 `test-runner.md` 中的验收命令。自动化测试使用隔离数据库；不要对生产数据运行。新增页面与流程已纳入发布前检查。

本版本数据库为 schema 2。升级与回退须遵循 [升级与回退](升级与回退.md)，数据库、上传文件、密钥及配置需要成套备份和恢复。不要让旧版本直接连接升级后的数据库。
