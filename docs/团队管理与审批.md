# 团队管理与审批（0.3 开发版）

## 初始化一个团队

1. 完成安装并登录超级管理员。
2. 在“系统管理 → 系统设置”填写系统名称、Logo、显示时区、单文件上传上限和回收站保留期（默认 30 天，可设为 7–365 天）。保存后生效，无需重启。数据库、存储路径和密钥仍由部署配置维护。
3. 在“部门管理”建立组织结构，在“用户管理”创建启用账号并分配部门。
4. 在“角色管理”使用团队成员、部门负责人或审阅人员模板，填写唯一编码和标识，确认勾选的权限后保存，再给用户分配角色。

模板只是可编辑的初始值，不赋予超级管理员身份。多个启用角色的权限取并集；赋予“全部数据”会扩大其他角色的数据范围。组织与权限配置写操作仍仅超级管理员可执行。

“工作台、事项与审批、站内通知”是启用账号的基础入口，不依赖角色菜单配置。用户管理等系统功能继续由 RBAC 控制。文件管理仍按上传者隔离，超级管理员可以管理文件；事项附件则使用单独的参与人校验。

## 提交和处理事项

- 在“事项与审批 → 新建申请”填写标题、说明并指定另一位启用用户作为审批人。搜索返回最多 50 个账号的姓名、登录名和编码，不返回联系方式等资料。
- 支持最多 10 个附件，单文件大小遵循系统设置。仅能关联自己的有效文件。成功提交后，附件保留作为审批凭证，不能从文件管理删除。
- 审批人在工作台和“待我审批”查看待办，也可从站内通知打开事项。可以通过或驳回；驳回必须填写原因。
- 申请人可以撤回尚未处理的申请。审批人停用后，申请人可撤回并重新指定其他审批人提交。
- 已通过、驳回或撤回的事项不可再次处理。申请人可在已驳回、已撤回事项详情中点击“修改后重新提交”：复制标题、说明和附件，修改后重新选择启用的审批人，生成关联原申请的新记录。原申请和处理记录保持不变；新审批人只获得新申请的访问权限。
- 列表可按标题、申请人或审批人姓名搜索，并按状态筛选。搜索词中的 `%`、`_` 等按普通字符处理。打开、关闭详情会保留筛选和页码。第一版不提供转交、加签、多级审批、流程设计器或业务表单配置。

系统管理员不会因为管理权限而自动看到所有事项，也不能代替审批人处理。事项正文、附件下载和审批记录仅对申请人及指定审批人开放。附件下载入口位于事项详情，不需要额外授予文件管理权限。

事务同时保存处理结果、审批记录和通知；并发提交不同决定时只允许一个成功，其他操作返回冲突并提示刷新。上传但未提交的文件仍保存在文件存储中，尚未关联审批，不属于审批凭证。

## 附件复用与存储维护

- 取消申请或从表单移除附件，不会自动删除已上传文件。在“我的未使用附件”中可复用、移入回收站或恢复自己的附件；新建申请时也可“选择已上传附件”。此入口无需文件管理权限。
- 本轮升级前的文件保留为普通文件，不根据文件名猜测用途；旧的未关联附件仍通过文件管理维护。已经关联审批的文件始终保留，驳回、撤回后也不能删除。
- 文件管理展示有效文件、回收站、未使用事项附件和到期可清理文件的数量与登记大小。普通用户只看自己的统计，超级管理员可看全局统计。未使用附件包含在有效文件内，到期可清理文件包含在回收站内，不能将四项相加；这些数值不代表磁盘总用量或可用空间。
- 超级管理员在“到期文件清理”中选择超过保留期的本地文件，确认后永久删除物理内容。没有定时自动清理，也不会自动删除尚未移入回收站的附件。执行前逐项复查保留期、恢复状态和审批引用。
- 清理开始后不能恢复；存储故障或数据库写入失败会留下可重试状态，修复故障后重新选择清理即可。已经清理的文件不再出现在回收站，元数据保留。远程对象存储暂不支持永久清理。

## 消息与时间显示

通知只对收件人可见，支持单条查看后标已读、全部标已读及仅看未读。页头计数每分钟刷新，回到窗口或当前窗口发生相关操作也会更新；不包含邮件、短信或即时推送。

设置中的时区用于工作台、事项、通知和设置修改记录；其他已有页面继续使用原有时间显示。时间在数据库中保持原始时间值，不因显示时区设置而改写。

## 验证和升级

运行仓库根目录 `test-runner.md` 中的验收命令。自动化测试使用隔离数据库；不要对生产数据运行。新增页面与流程已纳入发布前检查。

本版本数据库为 schema 3。升级与回退须遵循 [升级与回退](升级与回退.md)，数据库、上传文件、密钥及配置需要成套备份和恢复。不要让旧版本直接连接升级后的数据库。
